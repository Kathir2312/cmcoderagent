# Security review: the plugin for IntelliJ IDEA and the other JetBrains IDEs (13 October 2026)

Phase 7 item 7. Scope: everything new in Phase 7, meaning the plugin
(`jetbrains/`, its 2,500 lines of Java plus the shared JVM core compiled in),
its Gradle build, and the release gate's test build. The rest of the
repository was reviewed on 7 October ([scan-2026-10-07.md](scan-2026-10-07.md))
and its scanners still run in CI.

**Summary: nothing that reaches developers' PCs is vulnerable.** The plugin
ships no third-party library. The review found:

- vulnerable versions of three libraries in the build's own tools (fixed);
- one finding without a fix that our builds can't reach (a dated exception);
- one code cleanup (made).

The chat page in the IDE's browser (JCEF) is locked down as the other IDEs'
pages are.

## What was checked, with what

| Area | Check |
|---|---|
| The chat and navigator pages in JCEF | read in the code (`Panel.java`), and run by the release gate in a real IDE (below) |
| Java SAST | SpotBugs 4.10.4 with FindSecBugs 1.14.0 (maximum effort, all ranks) on the plugin's classes, with the IDE's classes on the classpath: **now in CI** for every change, failing on any security finding not reviewed; Semgrep (CI, the rule packs of 7 October) |
| What the plugin ships | Gradle dependency locking: `jetbrains/gradle.lockfile` says `empty=runtimeClasspath`, so no third-party library is in the plugin (the IDE provides the platform); the built zip holds the plugin's jar, the chat page, and cmcoder |
| The build's own tools | `jetbrains/buildscript-gradle.lockfile`: the 73 libraries the IntelliJ Platform Gradle Plugin brings, checked by osv-scanner in CI; CI fails if the lock files aren't current |
| The test build | the self-test (`src/gate`) and the page's test driver are only in the `-Pgate` build: the release build's jar is checked for `Gate.class`, and the page loads the test driver only when that class is present |
| Workflows | zizmor (no findings); the new SpotBugs downloads are pinned by SHA-256 |

## The page in JCEF

| Requirement | How | Checked by |
|---|---|---|
| No remote content | the page is a local file; Content-Security-Policy `default-src 'none'`, scripts only with the page's nonce, styles and images only from local files | code; the gate loads the real page |
| No navigation away | `onBeforeBrowse` cancels any main-frame navigation to another URL; a page that loads anyway is replaced by the plugin's own | the gate tries `https://example.com/` and checks the page stays |
| No new windows | `onBeforePopup` refuses every pop-up | code |
| Messages only from the plugin's page | the page's channel (`JBCefJSQuery`) takes a message only with a secret made for that page load; another page can't know it; frames are impossible (`default-src 'none'`) | code; the gate's messages go through it |
| Links | only `http:`/`https:` links, opened in the system browser | shared core (`Host.java`) |
| No developer tools in a release | the browser is built without the developer-tools menu item, and the context menu is empty | code |

The IDE's own registry can turn on JCEF's remote debugging port
(`ide.browser.jcef.debug.port`). That is the user's or the company's IDE
setting, not the plugin's, and it's off by default.

## Findings

### 1. Vulnerable libraries in the build's tools (high, fixed)

osv-scanner on the new lock file found:

- `jackson-core` / `jackson-databind` 2.21.4: 11 advisories, up to CVSS 7.5,
  fixed in 2.21.7;
- `jsoup` 1.22.2: 2 advisories, up to CVSS 8.7, fixed in 1.23.2.

They come from the IntelliJ Platform Gradle Plugin 2.19.0, the newest
release. They run only in CI, when the plugin is built, and are not in the
plugin. Fixed: `build.gradle.kts` asks for jackson's 2.21.7 BOM and jsoup
1.23.2 for the build's classpath, and the lock file holds those versions.

### 2. undertow-core 2.4.3.Final, CVE-2026-3260 (moderate, accepted until 2027-01-13)

A denial of service in Undertow's multipart parsing. It needs HTTP requests
sent to an Undertow server that reads request parameters. Undertow is only on
the build's classpath (the Gradle plugin), and our builds serve nothing over
HTTP. No fixed version is released yet. `jetbrains/osv-scanner.toml` skips it
with that reason until 13 January 2027, when osv-scanner reports it again.

### 3. SpotBugs + FindSecBugs (11 security findings: 1 fixed, 10 not exploitable)

| Finding | Where | Verdict |
|---|---|---|
| `USO`: static `synchronized` method locks on its class | `Brand.product()` | **fixed**: the name is read once, by a lazily initialised holder class, with no lock of ours |
| `COMMAND_INJECTION` | `AgentProcess.start`, `Diagnostics.output` | not exploitable: an argument list, no shell; the program is the bundled one, the shared copy or a full path the user set in the IDE's settings, which a project can't set |
| `COMMAND_INJECTION` | `ProgramLocator.prepare` | not exploitable: macOS `/usr/bin/xattr` on the plugin's own program folder |
| `PATH_TRAVERSAL_IN` | `ProgramLocator.sharedFolder`, `find`, `onPath` (3) | not exploitable: the user's own `CMCODER_CONFIG_DIR`, program setting (must be absolute) and PATH entries |
| `PATH_TRAVERSAL_IN` | `EditorContext.label` | not exploitable: a file's name for the chat's label; nothing is read |
| `IMPROPER_UNICODE` | `ProgramLocator.onPath` (2) | not exploitable: the PATH variable's name and Windows folders compared without case, as Windows does |
| `IMPROPER_UNICODE` | `Panel.samePage` | not exploitable: the page's own file URL compared without case; a different case names the same file on Windows and macOS, and the folder is the IDE's own system folder |

The not-exploitable findings are listed, method by method, in
`jetbrains/spotbugs/reviewed.xml`. CI fails on any other security finding,
including a new one of the same kind elsewhere. The JVM core's findings are
the ones the 7 October review found in Eclipse and NetBeans.

Semgrep: no error-level finding in the new code. The process launch already
carries its reviewed `nosemgrep`.

## Not covered

- Signing: the plugin zip isn't signed until the company has a certificate.
  The IDE installs it from disk without asking for a signature.
- Remote development (JetBrains Gateway, a remote backend): not supported,
  so not reviewed.
